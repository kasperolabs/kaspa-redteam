Attack library How it works GitHub

Attack your covenant before mainnet does.

Drop a SilverScript contract. It gets compiled, an honest spend is found for every path, and a library of known attacks is thrown at it. Every hostile transaction is signed for real and judged by rusty-kaspa's own consensus rules.

Drop a .sil file here or click to choose one. Several files that work together are tested as one project.
Constructor valuesthe tool fills them in for testing
Every value is filled in for testing. Change only the ones you know (amounts, limits, fee scripts, token hashes); the rest stay as they are. Keys and secrets are always played by the tool, which cannot sign with a real key or know a real secret.
Add a contract to see its values.
(NAME=VALUE lines, or the JSON you deploy with)
Baseline file (advanced)
Honest transactions from your own test harness, for contracts the search cannot spend on its own (token families, sibling programs). Format: BASELINE.md. Only use throwaway keys.
Compiled script (advanced)
Test the exact bytes your own pinned compiler made, not today's compile: its JSON output (with a bytecode hex) or a hex file. Keep the .sil above, and paste the constructor values it was compiled with; keys and hash locks are swapped for test ones, nothing else is touched.
Runs in an isolated process. The file is deleted when the run ends; nothing is kept.

What a finding means

Consensus accepted a transaction the attack expected it to reject. Each finding comes with that exact transaction, so anyone can replay it with kaspa-redteam replay.

What a clean run means

Every attack in the library was rejected on every path that was explored. It is not an audit. A path listed as unexplored was not tested at all.

Run it yourself

Same engine, on your machine, in CI, with no upload:

cargo install --git https://github.com/kasperolabs/kaspa-redteam kaspa-redteam
kaspa-redteam vault.sil -v
